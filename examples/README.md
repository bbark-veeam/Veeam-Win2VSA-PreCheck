# Example reports

Two sample HTML reports, so you can see what the tool produces before running it.
Download and open either in a browser — they are self-contained, with no external
scripts, styles or fonts.

| File | Verdict | Exit code |
|---|---|---|
| [`example-report-clean.html`](example-report-clean.html) | `REVIEW WARNINGS` | 0 |
| [`example-report-blocked.html`](example-report-blocked.html) | `MIGRATION BLOCKED` | 2 |

**The data in them is invented.** Server names, accounts, jobs and storage systems are
all fictional and deliberately generic. No real environment is represented.

They are generated by running the real tool against mocked Veeam cmdlets, not written by
hand, so they cannot drift away from what the tool actually emits.

## What the "clean" example shows

It is a server with nothing wrong with it, and its verdict is still `REVIEW WARNINGS`
rather than `READY`. That is expected and is the best result any server can get:

- **SEC-001 (four-eyes authorization)** and **SEC-003 (trusted-domain authentication)**
  always report `Manual`, because neither state is exposed to PowerShell at all. They are
  genuine questions for a human, on every server, and no amount of checking removes them.
- Both still carry the exact console path or condition to check, so answering them takes
  a moment rather than an investigation.

So treat `REVIEW WARNINGS` with only SEC-001 and SEC-003 outstanding as a clean bill of
health. Exit code 0 reflects that.

Note also that every clean result says **what it examined** — "3 managed agent(s)",
"2 stored credential(s) were examined", "the list was read successfully and is empty".
That is deliberate: a result that says only "none found" reads exactly the same whether
the check inspected everything and found nothing wrong or inspected nothing at all.

## What the "blocked" example shows

A deliberately awkward server, to show how findings are ranked and grouped:

- Two hard blockers that stop the migration outright — a **Cloud Connect deployment**, and
  a source running **13.1**, which cannot migrate.
- A **SureBackup SQL Server Checker Script**, which is Windows-only and will fail on the
  appliance.
- Actions that are fixable before migrating: a **socket licence**, an **agent below v13**,
  a **disabled agent policy**, a **machine-local repository account**, and **console role
  assignments** in a form the appliance login will not accept.
- Warnings and manual items for things that migrate but need attention afterwards, such as
  **CDP policies** and a **NetApp ONTAP** integration.
- Pre-migration next steps in their own section, which never affect the verdict.

The exit code is 2, so an unattended run can act on the verdict without parsing the report.

## Regenerating them

They are rebuilt from the development tree, not from this repository:

```powershell
pwsh -File internal/New-ExampleReports.ps1
```
